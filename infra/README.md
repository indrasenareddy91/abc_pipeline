# AWS infrastructure (Terraform) — Spark edition

```
S3 raw/<batch>/ ──event──► Lambda (all required files there?) ──► Step Functions
                                                                   │  Glue bronze ─► Glue silver ─► Glue gold
                                                                   │      (S3 Parquet layers)        (Redshift Data API)
                                                                   └─ any failure ─► SNS email
Redshift Serverless (warehouse: star schema, KPI + ops tables) ◄── Streamlit dashboard (Docker on EC2) ── "Run now"
```

## What it creates and why (one line each)

| Piece | Why |
|---|---|
| **S3 bucket** `raw/ bronze/ silver/ silver_changes/ quarantine/ ops/ glue/` | Landing zone (never modified) + medallion layers as Parquet + code for Glue. Private, encrypted, versioned, HTTPS-only. |
| **Lambda** files-arrived | S3 upload in `raw/<batch>/` → once every `required_files` pattern is present, starts the workflow with `{"batch": "<batch>"}`. Same files twice = one run. |
| **Step Functions** `<name>-pipeline` | Visible orchestration: Glue bronze → silver → gold (`startJobRun.sync`), retries when a job is busy, failure email. |
| **Glue 5.0 Spark jobs** `<name>-bronze/-silver/-gold` | Serverless Spark (Python 3.11, Spark 3.5): ingest, clean/validate/dedupe, load warehouse. Pay per second only while running. |
| **Redshift Serverless** `<name>-wg` / db `warehouse` | Warehouse for the star schema, SCD2, KPI SQL. Not public; reached via the Data API (IAM + Secrets Manager). Daily RPU-hour cap. |
| **EC2 t3.small** + Docker | Streamlit dashboard only (reads Redshift, "Run now" starts the workflow). No SSH — SSM only. |
| **ECR** | Dashboard image (same image locally and on the server). |
| **CloudWatch + SNS** | Glue job logs (`/aws-glue/jobs/<name>/output|error`), dashboard log; email on `ERROR` / `QUARANTINE_ALERT` lines and on workflow failure. |
| **Budget** | Email at 80 % of the monthly budget (default $20) and when the forecast passes 100 %. |
| Network | 1 public subnet (dashboard), 3 private subnets in 3 AZs (Redshift needs 3 AZs). No NAT gateway. S3 gateway endpoint. Flow logs (rejects). |
| Optional | `schedule_expression` (daily run), `enable_data_lake` (Athena over silver/quarantine), `github_repo` (OIDC deploy role), `enable_database` (RDS MySQL, unused by the pipeline — keep off). |

### Least privilege (who can do what)
- **Glue role**: read `raw/` and `glue/`; read/write/delete only `bronze/ silver/ silver_changes/ quarantine/ ops/` (explicit deny on `ops/server/`); Data API on its own workgroup; read the Redshift admin secret; write its own log groups.
- **Dashboard server role**: read the bucket (no write), Data API on its own workgroup + secret, `states:StartExecution/ListExecutions` on its own state machine, its own SSM parameter, its own log group, pull its own image.
- **Step Functions role**: start/watch its own 3 Glue jobs, publish to the alerts topic. **Lambda role**: list `raw/`, start the state machine.
- No secrets in code or tfvars: the Redshift admin password is generated by Redshift (`manage_admin_password`) and lives in Secrets Manager; the dashboard password is generated by Terraform and stored only in the encrypted SSM parameter `/<name>/app-config`.

## Contract with the code (job arguments / env)

Glue job `default_arguments` (the job scripts copy the UPPER-CASE ones into `os.environ`):

| argument | value |
|---|---|
| `--batch_id` | from the workflow input `$.batch` (e.g. `day1`) |
| `--run_id` | the Step Functions execution name |
| `--data_root` | `s3://<bucket>` |
| `--RUN_MODE` `--WAREHOUSE` | `aws`, `redshift` |
| `--REDSHIFT_WORKGROUP` `--REDSHIFT_DB` `--REDSHIFT_SECRET_ARN` | `<name>-wg`, `warehouse`, admin secret ARN |
| `--extra-py-files` | `s3://<bucket>/glue/engine.zip,s3://<bucket>/glue/project.zip` |
| `--additional-python-modules` | `PyYAML==6.0.2` |
| `--custom-logGroup-prefix` | `/aws-glue/jobs/<name>` → logs in `/aws-glue/jobs/<name>/output` (stdout/stderr) and `/error` (Spark) |
| script | `s3://<bucket>/glue/jobs/{bronze,silver,gold}_job.py` |

Dashboard env (SSM `/<name>/app-config`): `RUN_MODE=aws DATA_ROOT WAREHOUSE=redshift REDSHIFT_WORKGROUP REDSHIFT_DB REDSHIFT_SECRET_ARN STATE_MACHINE_ARN AWS_REGION DASHBOARD_PASSWORD APP_LOG_GROUP PIPELINE_LOG_GROUP IMAGE_URL DASHBOARD_PORT`.

## Cost notes (ap-south-1, approximate)
- **Redshift Serverless**: billed per second only while queries run (60-s minimum per burst), 8 RPU base. Idle = $0 compute. The usage limit **deactivates** the workgroup after `redshift_max_rpu_hours_per_day` (default 10 RPU-h ≈ 75 min of query time ≈ a few $/day); it re-enables the next day. Raise it in tfvars if a demo day needs more. Storage ~$0.024/GB-month.
- **Glue**: ~$0.44 per DPU-hour, per second, 1-minute minimum. Each job = 2 DPU (G.1X × 2) → a 2-min job ≈ $0.03; a full day1+day2 run ≈ $0.20.
- **EC2 t3.small** ~$0.022/h (~$16/month if left on; stop it when not demoing). Lambda, Step Functions, S3, CloudWatch: cents.
- No NAT gateway, no load balancer, no customer-managed KMS keys (each would add $1–32/month).

## Deploy (AWS CloudShell, ap-south-1)

One-time CloudShell setup (home is only 1 GB, so the provider cache goes to /tmp):
```bash
mkdir -p ~/bin /tmp/tfcache && cd /tmp
curl -fsSLo tf.zip https://releases.hashicorp.com/terraform/1.13.4/terraform_1.13.4_linux_amd64.zip && unzip -oq tf.zip -d ~/bin && rm tf.zip
echo 'export PATH=$HOME/bin:$PATH; export TF_PLUGIN_CACHE_DIR=/tmp/tfcache; mkdir -p /tmp/tfcache' >> ~/.bashrc && source ~/.bashrc
# upload the repo zip (Actions -> Upload file) and unzip it, or git clone
```
The state bucket already exists in this account (`tfstate-<account-id>-ap-south-1`, from `infra/bootstrap`). New account? `cd infra/bootstrap && terraform init && terraform apply` first.

```bash
cd infra/stack
cp terraform.tfvars.example terraform.tfvars    # project_name = hack (reused for any problem)
cp backend.hcl.example backend.hcl              # key = hack/dev/terraform.tfstate
terraform init -backend-config=backend.hcl
terraform plan
terraform apply                                 # ~5-10 min (Redshift workgroup is the slow part)
terraform output useful_commands
```
Then **confirm the SNS subscription email**, and deploy the code (from the repo root):
```bash
cd ../..
bash scripts/deploy.sh hack-dev           # Glue code -> s3 glue/, dashboard image -> ECR, restart dashboard
bash scripts/e2e_aws.sh hack-dev day1 day2   # upload sample batches, wait for runs, query Redshift
terraform -chdir=infra/stack output -raw dashboard_url; terraform -chdir=infra/stack output -raw dashboard_password
```
Only rules/SQL/config changed? `SKIP_IMAGE=1 SKIP_SERVER=1 bash scripts/deploy.sh hack-dev` (Glue picks up the new zip on the next run).

Run a batch by hand: `aws stepfunctions start-execution --state-machine-arn <state_machine_arn> --input '{"batch":"day2"}'`.

**Trigger rule:** a run starts when every `required_files` pattern is present in `raw/<batch>/`. With `["transactions*"]`, upload transactions **last** (e2e_aws.sh does). Leaving it empty starts one run per uploaded file.

## Save money / destroy
```bash
aws ec2 stop-instances --instance-ids <server_instance_id>     # dashboard off; Redshift/Glue cost nothing when idle
terraform destroy                                               # after the hackathon: deletes everything (bucket data too)
```
Glue creates `aws-glue-assets-<account>-<region>` (temp dir) on first run; delete it by hand if you want a clean account.
The Redshift admin secret is deleted with the namespace.

## Security scan (checkov) — accepted on purpose
- Customer-managed KMS keys (S3, logs, ECR, SSM, SNS, Redshift namespace, Scheduler, Lambda env): AWS-managed/owned encryption is on everywhere; CMKs cost $1/month each.
- Glue security configuration: would need a KMS key for CloudWatch encryption and renames the log groups (breaks the alarms). Data in S3 is SSE-S3 encrypted by the bucket default.
- 1-year log retention, S3 access logs / replication / event notifications on the state bucket: cost, not needed for a demo.
- Public IP + port 80 on the dashboard server: needed without a NAT/load balancer. Restrict with `dashboard_allowed_cidrs`; the dashboard has a password.
- Lambda without VPC / DLQ / X-Ray / code signing / reserved concurrency (new accounts have only 10 concurrent executions, reserving fails); Step Functions without X-Ray.
- Mutable ECR tag `:latest` (deploy.sh also pushes a git-sha tag). EC2 detailed monitoring: cost.
- `aws_availability_zones` not pinned to zone ids: the first 3 AZs of ap-south-1 are stable.
- RDS findings (Multi-AZ, enhanced monitoring, deletion protection) only apply when `enable_database = true`.

## Known limits (say these if asked)
- Glue and the dashboard use the Redshift **admin** secret. Production: a separate least-privileged DB user per app.
- Data loads into Redshift use multi-row INSERTs via the Data API (fine for MBs); for GBs use `COPY` from S3 with an IAM role on the namespace.
- One Glue run at a time per job (`max_concurrent_runs = 1`); a second batch waits (workflow retries on `ConcurrentRunsExceededException`).
